# 形态二：Tauri 桌面版

外壳刻意做得极薄（`src-tauri/src/main.rs` 约 365 行 + `src-tauri/src/cli.rs` 约 1170 行，
后者里有三分之一是单元测试），
只做五件事：**开原生窗口、挂中文菜单、弹「关于」、「把命令行/文件关联带上来的抓包交给页面」、
「`--csv` 命令行导出」**（最后一件在 `cli.rs`，见下面「命令行导出 CSV」一节）。
解析与界面 100% 复用前端那一套，所以桌面版和浏览器版表现完全一致。

---

## 先说清楚：不能一次构建出三个平台

Tauri（和 Electron 一样）**不支持交叉编译**。在哪个系统上打包，就只能出那个系统的产物。

原因在最后一步链接：Windows 要链 WebView2 loader + MSVC 运行库，macOS 要链 WKWebView + Cocoa，
Linux 要链 WebKitGTK + GTK。想要各平台的包，就得在对应架构的系统上各跑一次 ——
本仓库把这件事交给 [CI 矩阵](ci.md)，10 个目标一起出。

**但代码本身是跨平台的**：`src-tauri/` 那一份 Rust 在三个平台直接编译，
唯一的平台分支是 —— macOS 通过 `RunEvent::Opened` 接收「用 PDScope 打开」事件，
Windows / Linux 走命令行参数。这个差异已经写在 `main.rs` 里，不需要使用者关心。

## 三条构建命令（在**对应平台**上执行）

```bash
npm install             # 只装 @tauri-apps/cli
npm run app             # 开发模式：开原生窗口，改前端即时生效
npm run app:exe         # 只出可执行文件，跳过安装包（最快，完全离线）
npm run app:build       # 出当前平台的全部安装包
```

| 平台        | 只出可执行文件        | 出安装包             | 安装包产物                                          |
| ----------- | --------------------- | -------------------- | --------------------------------------------------- |
| **Windows** | `npm run app:exe`     | `npm run app:win`    | `bundle/nsis/PDScope_0.3.3_x64-setup.exe`（NSIS）<br>`npm run app:build` 还多出 `bundle/msi/PDScope_0.3.3_x64_zh-CN.msi` |
| **macOS**   | `npm run app:exe`     | `npm run app:mac`    | `bundle/dmg/PDScope_0.3.3_x64.dmg` + `bundle/macos/PDScope.app` |
| **Linux**   | `npm run app:exe`     | `npm run app:linux`  | `bundle/appimage/PDScope_0.3.3_amd64.AppImage` + `bundle/deb/PDScope_0.3.3_amd64.deb` |

产物在 `src-tauri/target/<三元组>/release/` 下 —— **显式传 `--target` 时路径里会多一层三元组目录**，
不传才是 `target/release/`。三个平台的依赖见[环境准备](env.md)。

> **`app:exe` 产出的那个可执行文件就是绿色版**：拷到任何同架构的机器上双击即用，
> 不安装、不写注册表（Windows 上需要系统有 WebView2 运行时）。`app:build` 才是「绿色版 + 安装包」。
> CI 会把绿色版单独压成 `PDScope-<目标>-portable.zip` 供下载。

> **MSI 的码页跟着语言走，这一项不能省。** `tauri.conf.json` 里配了
> `bundle.windows.wix.language: "zh-CN"`：MSI 数据库默认是 1252（en-US）码页，而本项目的
> 文件关联描述是中文，不改这一项 `light.exe` 会以 `LGHT0311`（字符串含码页外字符）直接拒绝出包。
> 所以 MSI 文件名带 `_zh-CN` 后缀，安装界面也是中文的。

> **安装包需要联网一次，可执行文件不需要。** `--no-bundle`（即 `app:exe`）只用本机已有的编译器，
> 完全离线；打安装包时 Tauri 会去 GitHub Releases 下载打包辅助程序（NSIS、WiX、appimage 工具，
> 下载完校验哈希）。不想在本机装这一堆、或者要别的平台的包，交给 [CI](ci.md)。

## 怎么打开一个抓包文件

四种方式，任选（`.atkcc` 与 POWER-Z 的 `.sqlite` 都可以）：

1. **菜单**：文件 → 打开抓包…（`Ctrl/⌘+O`）
2. **拖拽**：把抓包文件拖进窗口（`dragDropEnabled: false` 就是为这个设的 ——
   否则 Tauri 会吞掉 HTML5 拖放事件）
3. **命令行**：
   ```bash
   pdscope.exe "D:\抓包\绿联70w.atkcc"
   pdscope.exe "D:\抓包\山泽60w.sqlite"
   ```
4. **拖到 exe 图标上**，或装了安装包后**双击 `.atkcc`**（`tauri.conf.json` 里声明了 `.atkcc` 文件关联；
   `.sqlite` 是通用扩展名，没有抢来当关联，走前三种方式即可）

第 3、4 种走的是同一条路：外壳读文件字节 → 通过 IPC 交给页面 → 页面交给解析内核。
为什么绕这一圈？因为浏览器的安全模型不允许页面读任意本地路径；这样前端对「文件从哪来」完全无感，
换成单文件版后照样能跑。**格式判定也在页面里做**（看文件内容，不看扩展名），
所以外壳不需要知道这次打开的是哪一种抓包。

**每次都新开一个标签**，不会顶掉已经打开的那份 —— 上面四种方式可以反复用，想同时看几份就开几次。
（同一份文件重复打开也会各占一个标签：拿到「改动前 / 改动后」两个版本时，正好左右切着对比。）
一次失败不会牵连别的：坏文件只让**它自己**那个标签变红，其它抓包照常可用。

## 命令行导出 CSV（不开界面）

给脚本用的一条路：**不弹窗口**，把抓包解出来直接写成 CSV，完事打印一行摘要就退出。

```bash
pdscope.exe "D:\抓包\绿联70w.atkcc" --csv                    # 输出到 D:\抓包\绿联70w-ch0.csv
pdscope.exe "D:\抓包\绿联70w.atkcc" --csv "D:\出\绿联.csv"    # 指定输出路径
pdscope.exe "D:\抓包\山泽60w.sqlite" --csv --out 山泽.csv      # 写法二（等价）
pdscope.exe "D:\抓包\apple_40w.atkcc" --csv --channel 3       # 多通道文件指定通道（默认自动挑）
pdscope.exe "D:\抓包\ufcs_vivo.sqlite" --csv --limit 500      # 只导前 500 条（取样 / 排查）
pdscope.exe "D:\抓包\绿联70w.atkcc" --csv --out - > 出.csv    # CSV 打到标准输出（可接管道）
pdscope.exe --help                                            # 用法；--version 看版本
```

| 选项              | 说明                                                                       |
| ----------------- | -------------------------------------------------------------------------- |
| `--csv [路径]`    | 导出 CSV。省略路径 = 与输入**同目录**的 `<名字>-ch<通道>.csv`（与界面导出的命名一致）；`-` = 标准输出 |
| `--out <路径>`    | 同上，写全一点更清楚（`--csv=路径` 也认）                                   |
| `--channel <N>`   | 指定通道（多通道 `.atkcc` 默认自动挑「像 CC 线」的那条）                     |
| `--limit <N>`     | 只导前 N 条报文                                                             |
| `--bom`·`--no-bom`| 强制带 / 不带 UTF-8 BOM（默认见下面「编码」一节）                            |
| `-h/--help`·`-V/--version` | 用法 / 版本                                                         |

**退出码**：`0` 成功 · `1` 导出失败（文件坏了、写不进去、页面异常）· `2` 用法不对。
失败时会把已经写了一半的 CSV 删掉 —— 不留一个「看起来导出成功了」的残缺文件。

**输出长这样**（提示语走标准输出；`--out -` 时让位到标准错误，好让 stdout 只有 CSV）：

```text
  输出    D:\抓包\绿联70w-ch0.csv
  · 分块 8/16 · 已解出 348 条

PDScope 0.3.3 · 命令行导出
  输入    D:\抓包\绿联70w.atkcc
  来源    ATK-C 原始采样 · USB PD · ch0
  采样率  2.50 MHz
  报文    348 条 → 导出 348 行（D:\抓包\绿联70w-ch0.csv · 128.4 KB）
  时长    12.913 s · 解码 431 ms
  ── 备注 ──
  · 采样率按「文件声明」取用：2.50 MHz，时标换算以它为准
```

### 同一份 CSV，同一套代码

命令行导出的 CSV 与界面「另存为 → CSV」**逐字节同款**（UTF-8 带 BOM、CRLF 行尾、每列加引号），
因为三者（界面 / 桌面版命令行 / `node tools/cli.js --csv`）用的是同一个模块
`src/js/core/csv.js`，列名与转义只有一处定义。差别只有一处，是刻意的：

* **命令行导的是全部报文**，界面导的是**当前筛选结果** —— 命令行里没有筛选这个概念。

### 编码：一律 UTF-8，与终端 / 控制台类型无关

CSV 的字节由程序自己产生（页面算出文本 → 外壳按 UTF-8 写），**从不经过控制台的代码页转换**；
启动时把控制台输出代码页切成 65001 只影响屏幕上那几行提示语的显示，不改动任何字节。
所以「换个 GBK 控制台/老终端，导出就乱码」这种事在这里不会发生。

BOM 按出口分（BOM 是给 Excel 认 UTF-8 用的，进了管道就只剩碍事）：

| 出口                                   | BOM | 理由                                                     |
| -------------------------------------- | --- | -------------------------------------------------------- |
| `--csv <路径>` / 默认落盘名             | 带  | 双击就能用 Excel / WPS 打开，中文不乱码                   |
| `--out -` **被重定向到磁盘文件**        | 带  | 本质上还是在写文件（Windows 用 `GetFileType` 认出来）     |
| `--out -` 接管道（`\| more`、`\| python`） | 不带 | 那三个字节会污染下游                                     |

`--bom` / `--no-bom` 可以强制任意一种。

> **唯一管不了的**：PowerShell 的 `>`。它会把子进程的输出**当文本解码再重新编码**
> （5.1 默认写 UTF-16LE；控制台代码页是 GBK 时还会把中文弄坏）—— 这一步发生在我们的进程之外。
> 要落盘就**直接给路径**（`--csv 出.csv`），或者用 cmd 的重定向（`cmd /c "... > 出.csv"`，字节级）：
>
> ```powershell
> & .\pdscope.exe $f --csv ([IO.Path]::ChangeExtension($f, 'csv'))   # ✔ 程序自己写 UTF-8
> cmd /c "pdscope.exe `"$f`" --csv --out - > 出.csv"                  # ✔ cmd 字节级重定向
> & .\pdscope.exe $f --csv --out - > 出.csv                           # ✘ PowerShell 会重编码
> ```


### 它内部是怎么做的（以及为什么这么做）

Rust 侧一行协议代码都没有，**解析全在前端**。所以命令行导出不是「再写一套解析」，而是：

```text
  PDScope.exe 抓包.atkcc --csv
       ├─ ① 解析参数（cli.rs）
       ├─ ② 开一个**不显示**的窗口把 dist/PDScope.html 加载起来
       ├─ ③ 页面就绪后注入脚本：读文件字节 → PDScope.exportCsv() → 按行分块回传
       ├─ ④ 每块追加落盘，最后打印摘要并按退出码收场
       └─ ⑤ 退出进程，一帧界面都不给用户看
```

绕这一圈是为了**不出现第二份解析实现**：命令行导出的结果就是「打开这个文件、点导出」的结果。
代价是命令行模式也需要系统里有 WebView 运行时（与界面形态的要求一致，见[已知限制](limits.md)）。

窗口全程 `visible: false`（`tauri.conf.json` 里配的，界面模式在 `setup` 里 `show()` 出来，
顺带省掉一次白屏）。隐藏窗口里跑解码是安全的：解码让出主线程用的是 **MessageChannel**
而不是 `setTimeout`（见 `src/js/core/bmc.js` 里那段实测），不吃「后台页定时器被钳到 1 秒」那一套；
保险起见还会给 WebView2 追加三个「别因为窗口不可见就降级」的启动参数。

### Windows 上的两个坑（都是 GUI 子系统的通病）

1. **shell 不会等你**。`pdscope.exe` 是 GUI 子系统的可执行文件，从 `cmd` / PowerShell 启动时
   提示符立刻返回，脚本里下一条命令可能先于 CSV 落盘。要等就写成：

   ```bat
   start /wait pdscope.exe "D:\抓包\绿联70w.atkcc" --csv
   ```
   ```powershell
   Start-Process -Wait pdscope.exe -ArgumentList '"D:\抓包\绿联70w.atkcc"','--csv'
   # 或者把输出接一下管道，PowerShell 就会等：& .\pdscope.exe 抓包.atkcc --csv | Out-Null
   ```

2. **输出要自己挂回终端**。GUI 子系统的进程默认没有控制台，`println!` 会打在空气里。
   所以程序启动第一件事就是 `AttachConsole(父进程)`，并把控制台输出代码页临时切成 UTF-8
   （否则中文在 GBK 控制台上是乱码），退出前还原。输出被重定向（`> 出.txt`）时**不抢**用户的流。
   从资源管理器启动（没有父控制台）时只剩弹窗一条路：失败会弹一个错误框，成功则没有任何界面。

> 新改了这一块代码之后，`npm run app:csv` 会跑一遍
> [命令行导出自检](testing.md)（`tools/tauri-cli-check.mjs`）：把它导出的 CSV 与
> `node tools/cli.js --csv` 逐字节比，再顺带验默认输出名、`--limit`、`--out -` 与两种失败路径。
> 默认样本是现造的，不需要私有抓包。

## 多份抓包与标签栏

打开第一份文件后，顶栏下方长出标签栏（`#tabBar`），每份抓包一个标签：

| 标签上的东西 | 含义 |
| ------------ | ---- |
| **状态圆点** | 灰空心=还没解码 · 蓝呼吸=正在解码 · 绿=解码完成 · 黄=有告警（例如采样率声明与波形不符、协议未实现）· 红=这份文件打不开 |
| 文件名       | 太长时中间省略；悬停看完整名与状态文字 |
| 条数徽章     | 该份文件解出的报文条数（未解码时不显示） |
| `×`          | 关掉这一份 |
| 末尾 `+`     | 再打开一份（可多选） |

**怎么操作**

* **切标签**：点标签，或按 `Alt+1` … `Alt+9` 直接跳到第 n 份。
* **关标签**：点 `×`，或**中键**点标签。关掉当前标签后会接管它的邻居（先右后左）。
* **右键标签**：弹出菜单 —— 关闭 / 关闭其他 / 关闭全部。
* 标签栏在**只开着空白页**时整条收起，回到中间的「拖入抓包文件」引导。

**为什么要 lazy 解码**：拖 5 份文件进来时，5 份**同时**解码会互相抢 `S`、抢进度条、
还可能在第一份画出来之前先卡住几秒。所以容器加载（读字节 → 认格式 → 选通道）是每份都立即做的，
真正的报文解码推迟到**该标签第一次被激活**时，并且全部走同一条串行队列 ——
先打开的那份先解，界面立刻可用，其余在后台排队。

**状态是各份自己的**：筛选集合、时间窗口、选中行、通道选择、排序、时间轴档位（电压/电流 ↔ CC 线）
与**该档的纵轴缩放 / 平移**都存在标签对象上，切回来原样还原。只有**行高**、**详情面板宽度**与**时间轴高度**是全局偏好（那是「我怎么看」，
不是「这份数据是什么」），切标签不影响。

> 实现上把原来那个单例状态对象 `S` 保留成「**当前激活标签**」的别名，
> 所以几百处 `S.packets` / `S.filters` 一字未改，多文档是在它外面套了一层。

## 桌面版专属的菜单

| 菜单项                      | 快捷键          | 作用                           |
| --------------------------- | --------------- | ------------------------------ |
| 文件 → 打开抓包…            | `Ctrl/⌘+O`      | 弹系统文件对话框（可多选，每份各开一个标签）|
| 文件 → 关闭当前标签         | `Ctrl/⌘+W`      | 关掉正在看的这一份，邻居接管   |
| 文件 → 关闭全部抓包         | —               | 一次收掉所有标签，回到打开引导页|
| 文件 → 另存为（当前筛选）   | `Ctrl/⌘+S`      | 导出 CSV / JSON                |
| 文件 → 退出                 | —               | 关窗退出                       |
| 查看 → 搜索报文             | `Ctrl/⌘+F`      | 聚焦搜索框                     |
| 查看 → 切换主题             | `Ctrl/⌘+T`      | 明 / 暗                        |
| 查看 → 折叠 / 展开筛选栏    | `Ctrl/⌘+B`      | 收起左侧筛选栏                 |
| 查看 → 紧凑 / 舒适行高      | —               | 切换行高                       |
| 查看 → 全屏                 | `F11`           | 全屏 / 还原                    |
| 查看 → 开发者工具           | `F12`           | 打开 DevTools                  |
| 帮助 → 关于 PDScope         | —               | 版本 / 平台信息                |

> 「关闭当前标签」只动**一个**标签（页面里的 `PDScope.closeActive()`），不再整页 `location.reload()` ——
> 以前那么写会把别的标签一起清掉。只开着一份时两者效果一样，所以纯属行为升级。
> 带修饰键的这几项都交给原生菜单，页面那边主动让位，避免两套入口抢同一个键。
