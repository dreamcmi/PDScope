# 界面功能

| 能力                | 说明                                                                                         |
| ------------------- | -------------------------------------------------------------------------------------------- |
| **两种来源自动分流** | 打开文件只看**内容**（SQLite 魔数 + `pd_table` / `ufcs_table` 表名；ZIP 魔数）不看扩展名，`.atkcc` / `.sqlite` 拖进来都能解。顶栏「来源」chip 明示本份数据出自哪种设备 |
| **多份抓包 · 标签栏** | 拖拽 / 文件对话框都能一次给多份，每份占一个标签。标签带状态圆点（灰未解码 / 蓝呼吸解码中 / 绿完成 / 黄有告警 / 红打不开）与报文条数徽章；点选或 `Alt+1`…`Alt+9` 切换，`×` / 中键 / 右键菜单关闭（关闭 / 关闭其它 / 全部关闭）。**每份的筛选、时间窗口、选中行、通道、时间轴档位各自独立**，切回来原样还原；容器加载立即做，报文解码推迟到标签首次激活并走串行队列，拖一批进来不会被某一份大文件拖住 |
| **PD 规范基线** | 侧栏按当前文件选择 auto 或本地 PDF 对应的 2.0/3.0/3.1/3.2，改变后重新解码并更新详情、告警和导出。各文件独立保存；UFCS 禁用。Header `10b` 仅表示 3.x，显式基线是解释选择，不能证明设备的精确版本。参见 [四版本审计报告](pd-standards-audit.html) |
| **报文表**          | `# / SOP / 报文类型 / ID / 方向 / Obj / 时间 / VBUS-IBUS / 数据hex / 解析详情`，虚拟滚动，几万条也不卡 |
| **采样率来源标注**  | 顶栏显示实际采用的采样率并标出来源：`文件声明` / `波形实测` / `默认值`。声明与波形不一致时改按实测解码，并弹出提示；鼠标悬停可见 `channel.ini` 原文或原因。分析仪导出只有毫秒时间戳（`1.00 kHz`，标 `分析仪时间戳`），量级不同也能读 |
| **方向区分**        | `Source`（供电方）/ `Sink`（受电方）/ `Plug`（线缆 e-marker）三色徽章；PD 标注 `SOP / SOP′ / SOP″`，UFCS 标注物理链路 `D+ / D- / D±`（供电设备 D+ 为 TX、充电设备 D- 为 TX）。UFCS 的消息头里只有**接收方**地址，发送方按「规范单向命令表 → 容器链路字节 → 接收方地址」三级还原；只有落到第三级（纯推断）时详情里才写明「推断」—— 真实样本上**一条都不会落到第三级** |
| **GoodCRC 配对同色** | 每条 `GoodCRC` 自动取「它所确认的那条报文」的颜色，而不是笼统的控制色。配对依据：GoodCRC 是对报文的即时应答（实测恒为紧邻 1 条），并用 PD 规范要求的 *MessageID 相同* 交叉校验；被确认报文本身是坏包时退化为纯邻近匹配。悬停报文类型可见 `确认 #N · 类型`，详情面板「链路概览」里也有「确认的报文」一栏 |
| **选择性屏蔽**      | 按方向、SOP 类型、报文类别（控制/数据/扩展/VDM/异常）、**具体报文类型**（多选，带计数）、时间窗口、关键字任意组合过滤 |
| **快捷过滤**        | 一键屏蔽 GoodCRC 心跳包 / 只看 CRC 错误 / 只看功率协商 / 只看状态切换                        |
| **CRC 错误标注**    | 校验未通过的报文在表格里整行标红，并在时间轴对应位置画一条贯穿的高亮竖线；配合「只看 CRC 错误」可一键筛出来。分析仪导出**可能没存 CRC**（PD 的 `pd_table` 一律不存），此时统计行写「**CRC 未记录（分析仪不存）**」而不是「全通过」，详情面板也单列一行说明。UFCS 存不存 CRC 由容器定位阶段判定：存了就照实给「通过 / 失败」，没存才写「未记录」 |
| **时间窗口**        | 底部 VBUS/IBUS 时间轴可**拖拽刷选**一段区间，表格立即联动；右侧「复位视图」一键回到全览（时间 + 纵轴一起复位）|
| **横轴时间刻度**    | 时间轴底部标出时间（五等分，与淡竖网格线对齐），**单位随时长自适应**：不到 1 秒写 `0ms … 170ms`（10ms 以内再补一位小数，免得相邻两格同样）、不到 60 秒写 `0.00s … 2.50s`（两位数以上收成一位小数，如 `12.5s`）、更长写 `0:00 … 1:23`。刻度位置与左侧「时间窗口」滑杆是同一套归一化坐标，所以刷选、跟随选中、悬停读数（`0.042s`）三处的时间口径完全一致 |
| **曲线区可拖高**    | 时间轴**上方**有一条横向分隔条：**上下拖动**就能把曲线区拉高 —— 默认 158px 只够看大概，往上拖到**半个屏以上**才看得清台阶与纹波；也能压到最矮 92px 给报文表让位。拖过头会被夹住（报文表至少留 3 行），聚焦后 `↑` `↓` 微调（`Shift` 加大步长）、`Home`/`End` 到最矮/最高、`Enter` 或**双击**回默认。高度存 `localStorage`，属于**全局偏好**（和行高、详情面板宽度一样：那是「我怎么看」，不是「这份数据是什么」，切标签不变）|
| **纵轴可缩放 / 平移** | 曲线不再钉死在自适应量程上：**Ctrl/⌘ + 滚轮**缩放纵轴（以光标所在那条值为锚点，想看清哪一段就把鼠标放那儿；普通滚轮在曲线上不做任何事）、**上下拖动**平移、**双击曲线区**复位。平移的手势刻意避开横向刷选 —— 曲线区里的普通左键拖动仍然是刷选时间，平移请拖**左右刻度栏**、按住 **Shift** 拖、或**右键**拖（光标会在可拖的地方变成上下箭头）。刻度数字跟着视图走（放大后自动加小数位），调整过时「复位视图」按钮会点亮并显示当前倍率。**按标签、按档位各存一套**：切走再切回来还在，换文件 / 换通道回到自适应 |
| **POWER-Z `.pdStream`** | POWER-Z 的另一种导出（**只有报文、没有 ADC 波形**，见 [格式](format-pdstream.md)）：拖进来照常看报文表 / 详情 / 筛选 / 导出。「来源」chip 写明 `POWER-Z · .pdStream`，通道卡注明「无 ADC 波形」，时间轴走已有的「这份抓包没有模拟量轨迹数据」分支 —— 但**横轴时间刻度照常按事件铺开**，刷选时间窗口、点选报文都不受影响（刷选本来就只跟时间轴坐标有关，跟曲线无关）|
| **两档模拟量视图**  | 分析仪导出除了 VBUS / IBUS 还录了第三、第四路模拟量（POWER-Z 的 **CC1 / CC2**，UFCS 的 **DP / DM**）。量程与 VBUS 差一个数量级，叠在一起会糊，所以做成标题旁的 `电压/电流 ↔ 差分线` 两档切换（档名跟着文件走：PD 显示「CC 线」、UFCS 显示「DP / DM」）：纵轴刻度、悬停读数、曲线配色全部跟着换，**两档各自记自己的缩放 / 平移**。ATK-C 的 `bus.ini` 只有两路，这一档自动隐藏 |
| **插拔事件**        | 分析仪会把 DFP/UFP 的插入 / 拔出记成独立事件（ATK-C 只存波形，看不到这个）。顶栏「插拔」chip 给出计数（插入数 / 拔出数）。UFCS 容器记的是另一类事件，见下面「状态事件」 |
| **状态事件**        | UFCS 容器里有不承载报文的 8 字节状态事件行（`ts │ code │ 00 00 │ 0x40`）。顶栏给「状态事件 N」chip，明细（各 opcode 的条数）进 tooltip，**不当作报文计入**总数。语义无规范可对照，故不下「插入 / 拔出」这种定论 |
| **位域详情**        | 右侧面板逐位展开报文头（B15 扩展 / B14-12 对象数 / B11-9 MsgID / B8 PowerRole / B7-6 Rev / B5 DataRole / B4-0 类型）、扩展头、每个数据对象（PDO/RDO/VDM）的全部字段。分析仪来源的报文会在标题旁标「分析仪逻辑字节」，并把「实测码率」改称「BMC 码率」、「报文时长」改称「线上时长」—— 那是按 300 kbit/s 标称码率（600 kHz BMC 时钟）折算的估计，不是量出来的 |
| **分组配色**        | 每个数据对象（VDO / PDO / RDO / 扩展消息的数据块）单独成组，**相邻分组换色相**（8 色循环）并带左侧色条；`Source_Capabilities` 这种七八个 PDO 的长报文，不用读标题也能一眼看出边界。分组标题**滚动吸顶**，长列表翻到哪都知道自己在看第几个对象 |
| **详情宽度可拖 / 可收起** | 详情面板与表格之间的分隔条可**拖拽改宽**（下限 280 / 上限 900，且始终给中间表格留 420px，窄窗口下自动收紧），双击分隔条或按 `Enter` 回到 390 默认；也可聚焦分隔条后用 `← →` 微调（`Shift` 加大步长，`Home/End` 到最窄/最宽）。宽度存 `localStorage`，下次打开还在。按 `Esc` 或点右上 `×` 收起，**收起后窗口右缘出现一条 22px 的「详情」竖栏**，点它就能展开 —— 没有报文可点时（一行也没定位出报文的抓包）也回得来 |
| **UFCS 融合快充解析** | POWER-Z 录的 UFCS（`ufcs_table`）走**独立解析库**：UART 起止位 → 消息头四段位域（设备地址 / 消息编号 / 协议版本 / 消息类型）→ 控制 / 数据 / 厂家自定义三类消息 → **CRC-8（多项式 0x29，初值 0x00）**。17 条控制命令、14 条数据命令逐字段展开（`Output_Capabilities` 的每种输出模式、`Request`、`Source / Sink / Cable / Device / Error Information`、`Config_Watchdog`、`Refuse`、`Verify_*`、`Power_Change`、`Sink_Information_Extended`、`Test_Request`…）。方向按「规范单向命令表 → 容器链路字节 → 接收方地址」三级还原，`ACK / NCK` 与被确认报文配对。容器前缀是**实测归纳**的 9 字节布局（时间戳 / 游标 / 长度域 / 链路字节 / Training），先认它、认不出才退回「前缀长度 × 两种 CRC 读法」的穷举定位，**不假设结构** |
| **认不出的行如实说明** | UFCS 导出里有的行既定位不出报文、也不是状态事件（容器格式各家实现不一）：界面不装作解析失败，统计行写「已读入 N 行，但没有一行能认出 UFCS 报文」、表格空态换专门话术，模拟量轨迹照常可用。**容器里的状态事件行**（`ts │ code │ 00 00 │ 0x40`，不承载报文）单独统计成一个「状态事件 N」chip，明细进 tooltip，**不当作报文计入** —— 语义无规范可对照，故不硬起「插入 / 拔出」这种确定性的名字 |
| **POWER-Z `.ufcsStream`** | 与 PD 流共享外层布局，按 Raw 内容识别为 UFCS。支持报文、详情、筛选与导出，没有 ADC 曲线。两种流均保留逐报文电压/电流；缺失测量显示「—」、CSV 留空 |
| **导出**            | CSV（当前筛选结果）或 JSON（全部报文，含原始位域字段与 `ackOf` 配对序号）。CSV 的列名与转义由 `src/js/core/csv.js` 唯一定义，桌面版命令行 `--csv` 与 `node tools/cli.js --csv` 导出的是**同一份格式**（命令行导全部报文、不吃筛选；走管道时不带 BOM） |
| **其它**            | 明/暗主题、紧凑/舒适行高、上一条/下一条（↑↓）、`/` 聚焦搜索、`Ctrl/⌘+O` 打开、`Alt+1..9` 切标签、`T` 切主题、`G` 切 GoodCRC 屏蔽、折叠筛选栏 |
